审查对象：`src/dispatch.py`、`src/forecasting.py`、`src/run_models.py`、`src/prepare_data.py`，及四套主计算轨迹。审查者未修改上述实现文件。冻结哈希、精确结果和可重跑检查分别见 `independent-checks.json` 与 `run_independent_checks.py`。

运行：在项目根目录执行 `python3 review/run_independent_checks.py`。本机使用 `/Library/Frameworks/Python.framework/Versions/3.13/bin/python3`（带 SciPy）；bundled Python 带 openpyxl 但不带 SciPy，交接入口应区分两个环境。全部独立小测试退出码为 0，耗时约 0.50 秒。

## 结论

在“10 分钟间隔平均功率、交流母线侧充放电量、两个方向效率各 0.9、每日 SOC 强制回归给定目标、允许弃电和无限额紧急补购、减少购电退款后支付违约费、各时段最终净调整与 0 点基准结算”的明确假设下，核心实现没有发现阻断性数学、因果或收费错误。LP 是共同电池轨迹的期望成本近似计划；实际执行为因果反馈策略，并不是所写 LP 的原始电池轨迹，也不是完整多阶段问题的全局最优策略。

最终结论仍以交接文档正确披露下列边界、正式验证产物与完整结果文件通过最终审查为条件。

## 已独立验证的实质内容

### 1. LP 矩阵、量纲和优化目标

逐行核对变量切片和矩阵：`-q+c-d-e≤-n`，`E_next-E=eta*c-d/eta`，功率上界转为 `power/6` kWh，最后状态固定为终端值。调整期通过 `q-u+v=base` 实现 `u=(q-base)+`、`v=(base-q)+`；其目标中的 `1.5*p*u-0.5*p*v` 是相对于不变计划基准的增量。计划原价为优化中的常数而被省略，最终结算补回，逻辑一致。

场景价格与需求按同一历史日配对，目标中的紧急成本保留场景相关价格；常规购电项使用场景平均价格，符合期望值的线性分解。逐时确定价格时有 80% 分位点解释；价格与需求相关时需要价格加权的边际条件，不能直接说仍是普通 80% 分位数。

独立将一个时段、禁用储能的问题与穷举所有经验需求断点的精确期望成本比较：定价及价格随需求相关两例，LP 成本均与精确最小值一致，差为 0。四套主结果保存的 LP 最大对偶差约为 1.5e−10 至 1.75e−10 元。

`1e-7` 周转惩罚是为了选择数值稳定解，非题面经济成本。`expected_cost` 已将其排除，`lp_objective` 则包含，交接中不应把这两个字段等同。二者目标差的数量级应解释为数值正则项。

### 2. 去除同充同放是物理可行的

求解后按 `a=min(c,d/eta²)`，置 `c'=c-a`、`d'=d-eta²*a`，恰好保持 SOC 增量不变，并减少净耗电 `(1-eta²)*a`。因此在本题允许弃电的条件下不会破坏供电不低于需求约束。程序对返回数组重新计算 SOC 和紧急量，这点正确。四套实际轨迹也通过独立功率及非负检查。

### 3. 终端可达控制器

`execute_slot` 在实现当前自然充/放后，将下一步 SOC 投影至

`[max(Emin,Etarget-left*eta*Pmax/6), min(Emax,Etarget+left*Pmax/(6*eta))]`。

这是剩余 `left` 步对固定终端的精确单储能反向可达区间。由上一时刻可达性归纳，投影不会超过当前一步充放功率上界。补购不设上限、允许弃电使供电约束对投影后的动作始终可补偿。因此终端闭合证明成立。

独立检查 135 条极端路径、共 19440 步，覆盖效率 0.85/0.9/0.95、功率 4000/5000/6000 kW、终端 4800/6000/7200 kWh，以及持续盈余、持续短缺、交替盈缺、末段转盈/转亏。SOC 始终在范围内，最大功率误差为浮点量级，终端误差为 0。

### 4. 因果性

历史残差仅取严格早于决策日的完整日；日内负荷/电价校正只用本日已经发生的最近六小时数据；小时 PV 预报插值使用发布前最后已知的实际 PV 作锚点。0 点锚点取上一日 24:00，6 点预报第一个小时值对齐 7 点。未来小时插值没有引用未来实际 PV。

在第 101 天的 0/6/12/18 点分别把当时之后的实际负荷、PV、电价以及尚未发布的官方预报增加极大扰动，历史量保持不变。普通/官方 PV 两种模式下，当时全部净负荷及电价场景的最大变化均为 0。此结果证明已测试的信息边界未穿越；不把该有限测试称作覆盖所有潜在软件缺陷的形式证明。

### 5. 结算和输出轨迹

对 p=1、原计划100、最终80/120的四个结算案例独立核验：退款口径为90/130，不退款口径为110/130。若无退款且允许弃电，下降购电被原计划弱支配；对一组负需求至高需求的单时段实例，求解均不减少原计划。

## 最终交接需要关闭的边界说明

以下为说明和结论边界，当前未发现必须重写核心求解器的问题。

### MR-1：预报价值不能混同于全部日内重规划收益（中）

`q3_0only` 与全更新方案同时改变 PV 预报、负荷预测、实际 SOC 再规划机会，因此其费用差是日内更新整套政策的收益，不能全部归为新增 PV 预报的价值。主代理已在 `validate_models.py` 添加“保持负荷/状态更新，但始终使用 0 点 PV 预报”的同条件控制组。最终文档应报告该组，并根据结果判断新增 PV 信息的独立贡献；不要只用 `q2` 与 `q3` 的总费用差作此结论。

### MR-2：紧急补购可能被终端恢复充电触发（中）

实时反馈通常会优先减少充电以避免紧急采购，但强制恢复终端 SOC 时仍可能补购用于充电。当前四套方案中 `min(emergency,c)` 的总量分别约为11915.391、2291.511、10026.446、1802.154 kWh。此量是充电与紧急补购的同时发生量，不能称为严格因果归属的“全部充电导致的紧急电量”。应解释这是额外日闭合政策的代价；不能声称反馈已消除所有此类紧急采购。

### MR-3：一月用于选择，并非该段独立回测（中）

预测家族按1月15–31日误差选择，控制器按1月22–31日经济成本选择，历史一月残差也基于最终选中的家族回算。对2–12月不存在未来数据泄漏，但一月开发成本不能称为完全样本外业绩。2月1日初始6000的物理来源需要说明：例如1月维持SOC的可行暖机政策，而不是无说明重置电量。

### MR-4：近似与额外政策约束需直述（中）

每日6000闭合不是问题2–4明确要求的原生约束；LP的固定轨迹和执行的greedy反馈并不相同，故优化器对偶差只证明规划子问题求解准确，不证明执行政策接近未知全局最优。应以实际费用对照、消融和敏感性说明策略表现。

### MR-5：数据时段和实时测量假设（低）

把原表端点功率当作前一个10分钟的平均功率，是有必要但并非题面直接声明的离散化。实时控制中使用该时段实际净负荷应解释为“每10分钟观测/结算的离散响应模型”，不要声称已经验证连续时间内每一秒无短缺。原始端点与模板偏移的修正也须在最终交接中继续保留。

### MR-6：复现环境和数值参数（低）

运行计算所用系统 Python 有 SciPy，读取 Excel 的 bundled Python 有 openpyxl；提供明确入口或把依赖并入单环境，避免“一个未指定python3就能执行全部流程”的误导。0.001 价格情景截断、1e−7 周转惩罚、28日窗口、日内回归0.25方差正则均为建模/数值参数，需给出作用与来源，不能误称附件参数。
