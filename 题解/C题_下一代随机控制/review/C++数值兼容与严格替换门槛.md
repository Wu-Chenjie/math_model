# C++ 数值兼容与严格替换门槛

审查者：/root/independent_review。原年度实验保持暂停。本轮仅静态核对、独立小型 LP 与合成反馈测试；没有修改 src 或恢复实验。数值证据及源码/二进制快照哈希见 `cpp-math-independent.json`，可执行脚本为 `check_cpp_math_independent.py`。

## 数学与实证结论

C++ 凸 PL 卷积的实数公式正确。令 y=E−E′，其物理域为 [−ηM,M/η]；即时费用是 5p·max(0,a+max(−ηy,−y/η))。它与库存继续值作下确界卷积，再在原库存网格取值。价格非负、继续值凸是斜率合并的条件；库存弦插值仍是原近似，不能称作连续原问题精确解。稳定排序、端点、功率方向均与旧实现一致。

全 C++ M0 在实数层面也保留原递推：转移伪计数为 Sω，旧均匀分支计数为 1；空组仅将当期分布与均价回退到全场景，转移空行仍经平滑成为均匀行。每个已观测净需求先最小化，再组内加权；隐藏当期价格使用组均价，不提前揭示。终端优先级为 fixed6000 有限罚、切平面包络（包含零）、线性或零末值。未发现这些方程的移植错误。

但**全 C++ M0 不能认定为冻结策略的数值等价替换**。本审查独立测试再次出现 925.9259259259252 kWh 动作差，而同原目标值差仅 2.02×10⁻²⁸ 元。根因不是经济模型错误，而是 C++ 的矩阵积及组内求和顺序与 NumPy/BLAS 不同；极近平坦的分段线性目标会改变 argmin 的分支。保持原 action 函数也不够，因为它读到的 future/price 已变化。

当前兼容版本保留原 Python/BLAS 求和、插值动作和 tie 顺序，只替换 PL 卷积。AST 检查确认其 M0、加权 M0、M1 类与原类内容一致，仅导入的卷积实现变化。若每次卷积输出逐元素相同，由反向归纳可得每层值数组、继续项、均价相同；相同输入下在线 action 也相同。

本机、绑定版本的独立证据如下：

| 检查 | 结果 |
|---|---|
| 70 组卷积，含平坦/线性/切平面/终点罚及多网格 | Python/C++ 逐元素完全相同 |
| 48 个显式 c,d,E′,e 与 PL epigraph 独立 LP | 最大费用差 2.79×10⁻⁹ 元 |
| 14 组兼容 M0，含空组/非均匀/576 段 | cuts、future、price、initial_values 全同；探针动作全同 |
| 4 组兼容 M1，含固定/浮动价、自由/固定末值 | 三组值数组全同；探针动作全同 |

测试快照只限本机 NumPy、编译器和二进制版本，不是对所有平台、浮点输入的位级等价证明。显式 fma 是匹配本机 NumPy 插值的一个环节，不能单独保证整个原生 DP 相同。此前源码“不使用 FMA”注释已修正为禁止 fast-math、显式 FMA 用于匹配本机 NumPy arm64；本次修订未改变数值核心。

## 严格替换门槛

1. **模型与来源门槛。** 冻结数据、模型族、超参数、时域、末值、发布权限、策略选择规则与主 src 不变；源码、生成适配器、二进制、编译命令、NumPy/BLAS 环境全部绑定哈希。生成类 AST 一致；CSR 加速须验证完整矩阵、常量、界与求解器输入一致，不能只核对 LP 目标值。
2. **局部数值门槛。** 兼容 DP 应按逐元素相同检查中间数组与实际 action，而非用“目标差小”替代。保留退化、零均价、空组、非均匀概率、终点和长时域用例。任一动作差即拒绝作为相同冻结策略直接续跑；不新增 tie 容差、偏好或微小正则来掩盖，因为这些会修改原政策。
3. **真实闭环门槛。** 在原配置与真实截止点上比较完整短闭环，覆盖四问、M0/M1、48/72/96、午夜/非午夜、真实末点及已有 SDDP 午夜接口。核对 q、r、c/d、库存、紧急/弃电、projection、全部 release 和信息记录。合同值相同之外还要下次发布前的库存相同；否则后续合同可能分叉。存在的小容差差异应单列，不能升级为“策略等价”。
4. **续算门槛。** 新输出必须记录原生实现版本，避免只写未变 src 哈希而隐藏实际执行适配器。正式费用不能用于挑选数值实现。此前暂停的运行、已完成结果和新运行边界要明确；是否恢复由主任务依用户指令决定，本报告不授权恢复。

## 兼容保底

优先保留当前兼容版本的原归约与 tie 规则。若某类卷积在目标环境无法稳定对齐，可将该卷积或整个相应 DP 构造回退至旧实现；最保守方案仅加速经逐项验证的 CSR 构造，反馈保持旧代码。

若采用按“接近并列”触发回退，必须有覆盖该节点所有候选误差的可信界：真实候选间隔大于两倍目标误差界才足以证明 winner 不变。仅依据若干测试中观察到的 1e−6 不是统一界。并列/不确定时应重建原完整剩余 DP，再调用原 action，而不是只在 C++ future 上调用旧 action。无可信界时，不能用这种启发式检测宣称严格兼容；可使用逐次影子比较，或直接保留旧反馈。
